# How the class avatar behaves

Which pose shows when, how cues and spells play, and where the avatar sits. Its one-shot pace is `MotionStep.flight` (`.agents/skills/app-ui/references/motion.md`).

- **Which sessions:** a master whose class has a readable file (`TrackerAvatarCatalog`). Workers, shells and classes without art show none.
- **Poses:** `TrackerAvatarPose.pose(for:catalog:)` picks the steady pose, first match: blocked or needing input is calling out; working with a tool is that tool's pose (search studies, edit inscribes, a shell command by its command, web scries, agent, plan and other tools spellsong); otherwise sub-agents running is spellsong, working is pondering, and the rest is idle. Stopped and errored sessions are idle. A shell command's pose comes from the one table in `TrackerShellCommand` (Core): a reading command (ls, cat, rg, git log, gh pr view, ...) studies, a writing one (sed -i, mv, cp, git commit, gofmt -w, ...) inscribes, a network one (curl, git push, gh api, gh pr create, ...) scries, a spawn (`questmaster spawn`, `qm spawn`) summons, and anything else channels. The first program after leading `cd ... &&` segments, env assignments and `rtk` decides it. Codex's `exec_command` reads its command from the `Bash:` activity label, like the other agents' shell calls, and channels when it has no command text.
- **Director:** `TrackerAvatarDirector` (Core) decides the pose and the spell flights, and it is pure. **Nothing that has an end is cut:** an enter, a finish and a one-shot (a release, a catch, a summoning cast's beat, the bow) always play to their end, whatever else is wanted. A loop has no end, so it can be left at any time: when another pose is wanted its own finish plays (if it has one), then the next pose opens on its enter. A steady change holds the shown pose for `TrackerAvatarTiming.holdSeconds` (1.0 s), counted from the pose's arrival (it stops a tool that flickers on for a moment from starting a whole enter and finish), and waits for the pose's enter to end if that is longer; only the latest wanted pose is kept meanwhile, so the poses wanted in between are dropped and nothing replays a backlog. Calling out follows the same rule but skips the hold and the queue: it waits only for the block on screen to end (an enter or a finish, about 0.5 s at most; the beat on screen, when a cue is playing), the loop it leaves plays its finish first, and it comes on screen before the cues queued behind. A steady change, unlike calling out, waits for every queued or playing cue to end first. A turn that ends after at least `minimumBowWorkSeconds` (60 s) of work bows once, after its sub-agents stop; a shorter turn goes straight to idle. Attaching to a done session, or switching to one, shows no bow. Tracker events (`TrackerAvatarEventDetector`, from consecutive payloads; the first payload, an attach and a switch are a baseline) play as cues, each a short run of beats: a spawned worker summons (the summoning cast on its own beat, then release with the orb flying to the new worker's plate; while a summoning from a running spawn command is on screen, the orb waits for that summoning's finish), a message to a worker releases with the messenger, and a worker's report flies the wisp back to the avatar, then catches. A cue never cuts an enter, a finish or the bow: it waits for it to end. A cue that leaves a loop leaves it through the loop's own finish (a loop with no finish block is cut at once), which plays before the cue's first beat, so a report's wisp flies and a release's beat starts when it ends; the figure rests on the finish's last frame until a beat covers it. The loop doesn't come back after the cues: when the queue is empty (or calling out is wanted), the latest wanted steady pose shows on its enter, the pose that finished included. A cue that comes while the master is calling out leaves calling out through its finish, and calling out returns on its enter if still wanted. At most `queueCapacity` (4) cues wait behind the one playing; a burst past that drops the newest. A release or a catch that names its `strike_frame` has an entrance before its strike (`TrackerAvatarPoseAnimation.strikeLeadIn`: the start of the strike step), and its cue keeps to the strike. A release launches its spell (the orb or the messenger) as the strike step begins, not as the beat does, and the beat keeps its length; the director wakes at the launch (`nextChange`), and a late poll still launches it, before the next beat's. A catch starts early, over the end of the wisp's flight, so its strike step begins as the wisp lands: the wisp's beat is `MotionStep.flight` less the catch's lead-in, never below 0, so a lead-in as long as the flight or longer starts the catch with the wisp and the flight is never stretched. The flight's impact is the flight's own (the overlay draws it as the flight ends, whatever the beats do), so it stays on the landing. Without the key the lead-in is 0: the spell leaves with the beat and the catch follows the landing, as before. Under Reduce Motion no spell flies and the catch starts at once.
- **Playback:** a loop cycles each track on its own clock, so a 1-frame character and an 8-frame front run independently. A one-shot, an enter or a finish plays each track once, holds its last frame, and lasts as long as its longest track (`TrackerAvatarBlock.seconds`). Each track is a discrete keyframe run on its layer's contents, and a discrete keyframe holds each value only up to the next key, so every sequence closes on a repeated key. `TrackerAvatarFrame.beat` rises whenever a pose's cue starts, so a repeated one-shot plays again. Changes snap: the layers take contents, position, bounds and hidden at once (`TrackerAvatarLayerActions`), so there is no crossfade. `testAvatarPoseSwitchesLandAtOnceWithNoImplicitAnimation` checks the keys after a switch. Frames have no glow or floaters.
- **Finish:** when the steady pose leaves for another steady pose, its own `finish` plays first (any pose with a loop may have one, a cast or not), once the hold has run, and the new pose shows when it ends, opening on its own enter if it has one. It is skipped for a switch to the same pose, when the pose has no finish block (it then snaps), and under Reduce Motion; calling out and a bow wait for the finish like any change. Nothing cuts a finish: a change that arrives during one doesn't restart it, a cue or calling out waits for it, and the pose wanted at its end shows, with the poses wanted in between dropped. The finishing pose itself, wanted back by then, opens on its enter again. The finish's layers hold the frame at its elapsed time (`TrackerAvatarFrame.finishElapsed`).
- **Enter:** a steady pose with a `loop` may open it with an `enter`. The enter plays once when the pose comes on screen (on attach, a switch, a change, or calling out), then the loop starts from its own first frame (`TrackerAvatarFrame.enterElapsed`; the view plays the tracks with `TrackerAvatarFrameRig.showEnter`). A change, a cue or calling out that comes during an enter waits for its end (a change also for the hold, whichever ends later); a pose leaving after its enter then plays its finish from its first frame. A pose that continues, a new turn or the same pose back from a cue, doesn't replay it. Reduce Motion skips it. A summoning cast's cue plays its enter the same way, on its beat, then one loop cycle and its finish.
- **Slot:** an attached plate reserves a fixed slot after the scrolling plate list, standing `TrackerListMetrics.avatarBannerGap` (10pt) above its session banner, which sits above the pinned shell section. Shell rows and no known attachment reserve neither slot nor banner. Its height is
  the tallest bundled class's idle figure, rounded up to 5pt, and its width matches a master plate. The avatar's sole stays
  on the slot's bottom edge for every pose, and that edge is `avatarBannerGap` above the banner's top (the gap is outside the slot, so the hand point moves with it); art below the feet shows in the gap. A class change swaps the pose
  without changing the slot's size or moving the plate list or session banner.
- **Flights:** `TrackerSpellPath` (Core) decides where a spell flies, from the layout. A spell leaves the avatar's hand (`handPoint` in the avatar's slot) and lands on the Worker Log's left edge, level with the hand and clamped into the panel's height; with no Worker Log showing (the dock hidden, its bottom panel on artifacts, or only Version Control), it leaves the window's right edge at the hand's height and its impact is not drawn. A returning wisp runs back from that same spot and impacts on the hand. Every worker meets the same spot. `TrackerFlightOverlay` (App) draws each flight over the whole window, above the tracker, terminal and dock, with no hits, no keys and no first responder. The flight takes `MotionStep.flight` (1.0 s) along an arc `TrackerAvatarDesign.flightArcHeight` (40 pt) high, and a still impact holds for that time, then fades (frames play once instead; see Spell frames). The overlay reads the Worker Log's frame from the bottom dock view (`AppDelegate.workerLogWindowFrame`) and the hand from the avatar's view (`TrackerAvatarHandle`), not from SwiftUI preferences (`TrackerAvatarFlights.swift`).
- **Reduce Motion:** the poses still change, but each layer shows the first frame of its track, with no frame animation, moves, breath, blink, fidgets, enters, finishes or flights (`TrackerAvatar.updateMotion` stops them, and the director and fidgets skip theirs). A beat that was only a flight goes with it.
- **Constants:** `TrackerAvatarTiming` (Core) holds the pose hold and bow threshold. Block and frame times come from the animation file, fidget gaps from `TrackerAvatarFidgetTiming`, and drawing settings such as `pixelPoints`, blink timing and `flightArcHeight` from `TrackerAvatarDesign` (App).
