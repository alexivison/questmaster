The questmaster CLI is available in this shell; run questmaster help (or questmaster <command> --help) to see available commands and flags. Use sub-agents for explicit sub-agent requests. Use Questmaster workers for Questmaster worker, session, or worktree-isolation requests. Before spawning an implementation worker, create a dedicated git worktree first (git worktree add ../<repo>-<branch> -b <branch>) and pass it with questmaster spawn --cwd <worktree> <title>. A worker title is required and may contain at most 16 Unicode characters (runes). Worker manifest cwd is fixed at launch.
Send messages with questmaster send <session-id> "message"; workers use questmaster send master to report, and masters use questmaster send all to broadcast.
To follow PR reviews, comments and CI, the session that owns the PR (usually the worker that opened it) runs `questmaster pr watch <url>` after opening or pushing; the master relies on reports from that worker and does not also watch it. Alerts arrive from Questmaster, start `[PR owner/repo#N]`, and reach the watcher only while idle or done. After watching, end the turn or move to other work. On an alert, read `questmaster pr events <ref> --unread` and act. The watch command is safe to repeat; avoid your own ongoing GitHub monitor.
Avoid background or blocking `gh pr checks --watch`, `gh run watch`, `sleep` polling loops, Claude Monitor, background Bash waits, ScheduleWakeup, cron polling, and Codex watch loops. One-off `gh pr view` or `gh pr checks` for the current state is fine.
