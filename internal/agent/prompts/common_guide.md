The questmaster CLI is available in this shell; run questmaster help (or questmaster <command> --help) to see available commands and flags. Promote this session to a master with questmaster promote <session-id> if you need to spawn workers. Use sub-agents for explicit sub-agent requests. Use Questmaster workers for Questmaster worker, session, or worktree-isolation requests. If you promote and spawn implementation workers, create a dedicated git worktree first (git worktree add ../<repo>-<branch> -b <branch>) and pass it with questmaster spawn --cwd <worktree>. Worker manifest cwd is fixed at launch.
Send messages with questmaster send <session-id> "message"; workers use questmaster send master to report, and masters use questmaster send all to broadcast.
Questmaster-launched or continued Codex sessions with a per-session app-server get active-turn steering by default. If there is no active turn, steering is unsupported, the app-server is unavailable, or the session is older, external, or started without that server, send uses the durable Codex queue; if Codex native delivery is unavailable, it falls back to tmux. `send` reports `delivery_mode` (`codex-steer`, `codex-queue`, or `existing-transport`), which identifies the selected transport, not model receipt. If steer acceptance is uncertain, send errors without retrying, to avoid duplicates. Claude, Pi, OpenCode, and tmux targets keep their current transport behavior; transport acceptance does not confirm processing.
