The questmaster CLI is available in this shell; run questmaster help (or questmaster <command> --help) to see available commands and flags. Promote this session to a master with questmaster promote <session-id> if you need to spawn workers. Use sub-agents for explicit sub-agent requests. Use Questmaster workers for Questmaster worker, session, or worktree-isolation requests. If you promote and spawn implementation workers, create a dedicated git worktree first (git worktree add ../<repo>-<branch> -b <branch>) and pass it with questmaster spawn --cwd <worktree>. Worker manifest cwd is fixed at launch.
Send messages with questmaster send <session-id> "message"; workers use questmaster send master to report, and masters use questmaster send all to broadcast.
Use the default send queue when a message can wait for the next Codex turn; add --steer to send input into the active turn of a Codex TUI launched or continued by Questmaster. Questmaster starts a per-session Codex app-server with the matching session environment; if startup fails, it launches the regular local TUI. Older or externally launched Codex sessions, or sessions with no active turn or app-server, use the durable queue. If the app-server is unavailable while sending, `--steer` falls back to the durable queue; if the default queue is unavailable, the existing tmux fallback applies. `send --steer` reports `delivery_mode` (`codex-steer`, `codex-queue`, or `existing-transport`), which identifies the selected path but does not confirm model receipt. If steer acceptance is uncertain, the send errors without retrying, to avoid duplicates. For Claude, Pi, OpenCode, and tmux targets, --steer keeps the current transport and does not confirm processing.
